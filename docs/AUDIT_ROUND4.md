# 第四轮代码审计（2026-10-18 深夜）

> 重点：不再只看"会不会崩"，而是看**论文要的数字有没有被正确记录**、**长跑中断能不能接上**、**复用会不会用错东西**。
> 结果：发现 8 处问题（其中 3 处会直接污染实验数据），全部修复；测试 36 → 40。

---

## 一、会让论文数据出错的（已修）

### 1. 缺"识别准不准 / 改对多少"的数字

原来的日志只有「噪声客户端数」「修正样本数」，没有和干净标签的对照。计划书第 9.1 节明确要求：**修正前/后标签正确率、正确修正与错误修正数量、客户端可靠性与实际噪声率相关性**。

新增 `fusion/analysis.py`，在 FedCorr 结束后（只读，不回流训练）计算：

| 指标 | 含义 |
|---|---|
| `label_accuracy_before/after` | 纠错前后的标签正确率 |
| `labels_changed` / `fixed` / `broke` | 改了多少、改对多少、改错多少 |
| `correction_precision/recall` | 纠错精确率与召回率 |
| `client_accuracy` / `precision` / `recall` | 客户端噪声识别（TP/FP/FN/TN） |
| `spearman_estimated_vs_true` | 估计噪声率与真实噪声率的秩相关 |
| `per_client` | 每个客户端的真实噪声率 vs 估计值 |

同时 `fedcorr_iterations.jsonl` 补了 `noisy_client_ids`、`estimated_noise`、`lid_accumulated` 三个字段。

### 2. 标签正确率的统计口径错了

`correction_metrics` 原来把**公共集**也算进去了。公共集从不参与训练、也从不被修正，混进去会稀释指标。已限定为 `split == "client"`。

### 3. 复用修正标签时不校验 FedCorr 配置

`reuse_correction=True` 时只要文件存在就直接用。如果改了 `iteration1`、`beta`、模型或随机种子，会静默沿用旧标签。

新增指纹（FedCorr 配置 + 模型 + 数据协议 + 种子 + manifest 摘要），不匹配自动重跑。

## 二、长跑可靠性（已修）

### 4. 没有断点续跑

FedDS 跑到第 150 轮崩了只能从第 1 轮重来。新增轮级 resume：

- `runtime.resume=true` 时每轮结束原子写 `*_resume.pt`（模型 + 轮号 + 标签）；
- 重启时自动从下一轮继续；
- **新增测试证明"续跑的结果与不中断完全一致"**（因为每轮的随机数由轮号派生）。

### 5. resume 不校验超参

改了 `local_bs` / `lr` 再 resume，会用旧模型继续跑，结果无法解释。新增指纹校验；但**故意把 `rounds` 排除在外**——"从 100 轮扩到 200 轮"正是 resume 的主要用途。

### 6. 日志与断点不同步

一轮的准确率先写日志、后写断点。如果正好死在这两步之间，恢复时这一轮会被重跑并重复记录。已改为：恢复时把日志截断到断点轮号。

## 三、健壮性（已修）

### 7. 配置校验缺口

- `arms` 里有重复项 → 会跑两遍、覆盖同一目录；
- `exp_name` 带 `../` → 可以把结果写出 `output_root` 之外；
- `save_every` 为负 → 取模行为异常。

三处都已加校验。

### 8. FedDS 的 CNN 没和官方对拍过

之前只对拍了 ResNet18/34、LID、FedAvg、DS，`CNNCifar` 一直是"看起来一样"。新增等价测试：**state_dict 键完全一致，同权重下前向输出逐位相同**。
